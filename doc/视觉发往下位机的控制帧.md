# 视觉 → 下位机 控制帧格式（下位机需要解析的部分）

> 视觉端（awake1.0）**现在就在发**这个格式，下位机只要按本文解析即可，
> 不需要改视觉端任何代码。文中所有样例都是从**正在运行的程序**里抓的真实字节。

## 0. 串口参数

| 项 | 值 |
|---|---|
| 波特率 | **115200** |
| 数据位/校验/停止位 | **8 / None / 1**（8N1） |
| 流控 | 无 |
| 端口 | 与 `ARQ` 姿态帧**同一个口**，双向 |

---

## 1. 帧格式

```
A  A  P  <pitch>  Y  <yaw>  F  <fire>  N  <frame>  C  <4位hex CRC>  %  \n
```

一行一帧，纯 ASCII 文本。

### 真实样例（可直接当测试向量）

从运行中的程序抓的原始字节，**逐字节必须一致**：

```
AAP0.00Y0.00F0N0C2c30%
AAP0.00Y0.00F0N1C3db9%
AAP0.00Y0.00F0N2C0f22%
AAP0.00Y0.00F0N391Cf318%
```

> 现在 `pitch=yaw=0.00`、`fire=0`，因为相机前没有装甲板（`found: 0`）。
> 有目标时 `pitch`/`yaw` 变成非零小数，`fire` 可能变 `1`，格式不变。

### 字段说明

| 字段 | 类型 | 说明 |
|---|---|---|
| `AAP` | 固定 3 字节 | **帧头**，大写字面量，无空格 |
| `P` 后面的数 | 浮点，**2 位小数** | **pitch 增量**，单位**度**，可正可负 |
| `Y` 后面的数 | 浮点，**2 位小数** | **yaw 增量**，单位**度**，可正可负，已归一化到 ±180° |
| `F` 后面的数 | 整数 | **fire**：`0` = 不开火，`1` = 开火（**只有这两个值**） |
| `N` 后面的数 | 整数 | **帧号**，单调递增（从 0 开始），用于丢帧统计 |
| `C` + 4 位小写 hex | 固定 5 字节 | CRC16，见第 3 节 |
| `%` | 固定 1 字节 | 字面量结束符 |
| `\n` | 1 字节 | 换行结束（`\r\n` 也发得出来，但当前只发 `\n`） |

## 2. 语义（**最容易搞错的地方**）

### 2.1 pitch / yaw 是**增量**，不是绝对角度

```
目标云台角 = 当前云台角 + (pitch, yaw)
```

视觉端算的是：

```
send_pitch = 目标pitch - 当前pitch          （取自最近一帧 ARQ 四元数换算）
send_yaw   = wrap180(目标yaw - 当前yaw)      （归一化到 ±180°）
```

所以下位机收到后应当**叠加**到当前角度上，而不是直接跳转到该角度。

### 2.2 fire 的触发条件

视觉端只在以下三条同时成立时才发 `fire=1`：

1. 有装甲板目标（`appear == true`）
2. 弹道解算判定可以开火
3. 增量总误差 `hypot(pitch, yaw) < 1.0°`

也就是说 `fire=1` 期间云台已经在瞄准点上。**建议下位机自己再做射速限制**
（例如每 `N` ms 最多出一发），不要每收到一个 `1` 就无脑连发——视觉端是
连续发流（约 100 Hz），`1` 会保持一小段时间。

### 2.3 没有目标时

`pitch = 0.00`、`yaw = 0.00`、`fire = 0`，**云台应保持不动**。

### 2.4 发送节奏

- 视觉端**每收到一帧 ARQ 就回一帧 AAP**，即约 **100 Hz**（与下位机发送频率同步）
- 这样增量始终基于最新的云台姿态，不会算错
- 发送的最小间隔被限制在 2 ms（≤500 Hz），不会把串口写队列撑爆

## 3. CRC 算法：CRC16-MCRF4XX

| 参数 | 值 |
|---|---|
| 多项式 | 0x1021（**反射后 0x8408**） |
| 初值 | **0xFFFF** |
| 输入/输出反射 | 是 |
| 结果异或 | 0x0000 |
| **覆盖范围** | 从帧首 `'A'` 开始，**到 `'C'` 之前**（不含 `'C'`） |
| 输出 | 4 位**小写** hex，高位补 0 |

```c
uint16_t crc16_mcrf4xx(const uint8_t *data, uint16_t len)
{
    uint16_t crc = 0xFFFF;
    for (uint16_t i = 0; i < len; ++i) {
        crc ^= data[i];
        for (int b = 0; b < 8; ++b) {
            crc = (crc & 1) ? (uint16_t)((crc >> 1) ^ 0x8408) : (uint16_t)(crc >> 1);
        }
    }
    return crc;
}
```

> 与 `ARQ` 帧用的是**同一个算法**，下位机已经实现过一遍，直接复用即可。
> 注意**不是** Modbus 的 0xA001。

## 4. 解析建议（C 参考实现）

```c
typedef struct {
    float pitch_deg;   // 增量
    float yaw_deg;     // 增量
    uint8_t fire;      // 0 / 1
    uint32_t frame;    // 帧号
} AapCmd;

/* 返回 1 = 解析成功且 CRC 正确；0 = 丢弃 */
int aap_parse(const char *line, uint16_t len, AapCmd *out)
{
    if (len < 12) return 0;
    if (line[0] != 'A' || line[1] != 'A' || line[2] != 'P') return 0;

    /* 找最后一个 'C'，其后必须有 4 位 hex（要留出 % 和换行的余量） */
    int cpos = -1;
    for (int i = (int)len - 1; i >= 3; --i) {
        if (line[i] == 'C') { cpos = i; break; }
    }
    if (cpos < 0 || cpos + 5 > (int)len) return 0;

    /* 校验 CRC：覆盖 [0, cpos) */
    unsigned want = 0;
    if (!parse_hex4(&line[cpos + 1], &want)) return 0;
    if (crc16_mcrf4xx((const uint8_t *)line, (uint16_t)cpos) != (uint16_t)want) return 0;

    /* 字段解析：注意用 sscanf 时把 line 在 cpos 处截断 */
    char body[64];
    if (cpos >= (int)sizeof(body)) return 0;
    memcpy(body, line, (size_t)cpos);
    body[cpos] = '\0';

    float p, y;
    int f, n;
    if (sscanf(body, "AAP%fY%fF%dN%d", &p, &y, &f, &n) != 4) return 0;

    out->pitch_deg = p;
    out->yaw_deg   = y;
    out->fire      = (uint8_t)(f ? 1 : 0);
    out->frame     = (uint32_t)n;
    return 1;
}
```

**健壮性要点**（视觉端发送侧就是按这些原则设计的）：

- 按 **`AAP` 前缀搜索**、按 **`%` 或 `\n` 切帧**、跨读块拼接 → 帧间混发任何其它数据都不会错乱
- CRC 失败的帧**直接丢弃**，不要用它（下位机继续用上一次的有效指令）
- 帧号 `N` 跳变可以用于统计丢帧，但**不要依赖它做控制逻辑**

## 5. 测试向量（必须逐字节一致）

| `C` 之前的部分 | 完整帧 |
|---|---|
| `AAP0.00Y0.00F0N0` | `AAP0.00Y0.00F0N0C2c30%` |
| `AAP0.00Y0.00F0N1` | `AAP0.00Y0.00F0N1C3db9%` |
| `AAP1.23Y-4.56F0N120` | `AAP1.23Y-4.56F0N120Cc328%` |
| `AAP-3.50Y12.30F1N9999` | `AAP-3.50Y12.30F1N9999Cdb00%` |

后两条是构造的例子（带负数、带 `fire=1`），用于验证解析器对符号和小数的处理。

Python 自检：

```python
def crc16_mcrf4xx(data: bytes) -> int:
    crc = 0xFFFF
    for b in data:
        crc ^= b
        for _ in range(8):
            crc = (crc >> 1) ^ 0x8408 if crc & 1 else crc >> 1
    return crc

for body in ["AAP0.00Y0.00F0N0", "AAP0.00Y0.00F0N1",
             "AAP1.23Y-4.56F0N120", "AAP-3.50Y12.30F1N9999"]:
    print(f"{body}C{crc16_mcrf4xx(body.encode()):04x}%")
# 输出：...C2c30%  ...C3db9%  ...Cc328%  ...Cdb00%
```

## 6. 联调验收

1. 下位机先按 **第 5 节**的四条测试向量跑通解析，CRC 和字段都对得上
2. 接上视觉，看下位机能否每秒解析到 **≈100 帧**、CRC 失败率 **0**
3. 相机前放一块装甲板，确认 `pitch`/`yaw` 变成非零并**跟随装甲板移动方向**
   （向左移动装甲板，看看云台是否往左转；方向反了就说明 pitch/yaw 的符号约定要核对）
4. `fire` 应在准星压住装甲板时短暂变 `1`

**方向核对**（如果转反了，优先怀疑这三点）：

- 四元数的 `w/x/y/z` 顺序是否和 `ARQ` 一致（`ARQ` 端已用 `w,x,y,z`）
- 云台当前角度的 `pitch`/`yaw` 从四元数取的方式（ZYX 欧拉角、弧度→度）
- `yaw` 增量归一化到 ±180° 是否生效
