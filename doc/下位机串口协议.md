| 项 | 值 |
|---|---|

## 1. 下位机 → 视觉：姿态帧 `ARQ`（**这是需要改的部分**）

### 1.1 格式

```
A  R  Q  <w>  X  <x>  Y  <y>  Z  <z>  C  <4位hex CRC>  %  \n
```

一行一帧，纯 ASCII 文本：

```
ARQ0.9522X0.1541Y0.1537Z0.2145Cb404%\n
```

- **固定前缀**：`ARQ`（三个大写字母，不能有空格）
- 然后是 4 个浮点数，顺序**必须**是 `w → x → y → z`，每个数前面是它的大写字母标签 `X`/`Y`/`Z`
- 数字用十进制小数即可，建议 `%.4f`（4 位小数 ≈ 0.01° 精度，够用）
  - 允许负数，例如 `ARQ-0.7071X0.0000Y0.7071Z0.0000C12e5%`
  - 不要用千位分隔符，不要用逗号当小数点
- `C` 后面跟 **4 位小写十六进制** CRC（高位补 0，例如 `0b3f`、`a65a`）
- `%` 是字面量结束符
- `\n`（或 `\r\n`）结束这一帧

### 1.2 四元数要求

- **单位四元数**，顺序 **w, x, y, z**（w 是实部，放第一个）
- 坐标系沿用你们现有约定：X 前 / Y 左 / Z 上
- 视觉端收到后会再做一次归一化，但**请下位机保证输出就是单位四元数**（实测你们现在发的模长是 1.000000，很好，保持即可）

### 1.3 CRC 算法：CRC16-MCRF4XX

| 参数 | 值 |
|---|---|
| 宽度 | 16 |
| 多项式 | 0x1021（**反射后 0x8408**） |
| 初值 | **0xFFFF** |
| 输入/输出反射 | 是 |
| 结果异或 | 0x0000 |
| **覆盖范围** | 从帧首 `'A'` 开始，**到 `'C'` 之前**（不含 `'C'`） |
| 输出 | 4 位小写 hex，高位补 0 |

C 语言实现（可直接拷）：

```c
uint16_t crc16_mcrf4xx(const uint8_t *data, uint16_t len)
{
    uint16_t crc = 0xFFFF;
    for (uint16_t i = 0; i < len; ++i) {
        crc ^= data[i];
        for (int b = 0; b < 8; ++b) {
            crc = (crc & 0x0001) ? (uint16_t)((crc >> 1) ^ 0x8408)
                                 : (uint16_t)(crc >> 1);
        }
    }
    return crc;
}
```

> 注意：这个**不是** Modbus 的 0xA001。两者初值都是 0xFFFF、都反射，但多项式不同，
> 结果完全不兼容。实测你们之前用的就是 0x8408，保持一致。

### 1.4 组帧示例（C）

```c
char body[80];
int n = snprintf(body, sizeof(body), "ARQ%.4fX%.4fY%.4fZ%.4f", w, x, y, z);
uint16_t crc = crc16_mcrf4xx((const uint8_t *)body, (uint16_t)n);
char frame[96];
int m = snprintf(frame, sizeof(frame), "%sC%04x%%\r\n", body, crc);
uart_send((const uint8_t *)frame, (uint16_t)m);   // 一次性整帧发出
```

**整帧一次性发出**最好（不要在一个帧中间插别的字节）。即使中间插了别的数据，
视觉端也能靠 `ARQ` 前缀重新同步，只是会丢那一帧。

### 1.5 测试向量（必须逐字节一致）

用上面的 CRC 函数，下面这些结果应当完全对上：

| 帧内容（`C` 之前的部分） | 完整帧 |
|---|---|
| `ARQ1.0000X0.0000Y0.0000Z0.0000` | `ARQ1.0000X0.0000Y0.0000Z0.0000Ca65a%` |
| `ARQ0.7071X0.0000Y0.7071Z0.0000` | `ARQ0.7071X0.0000Y0.7071Z0.0000C2dd9%` |
| `ARQ-0.7071X0.0000Y0.7071Z0.0000` | `ARQ-0.7071X0.0000Y0.7071Z0.0000C12e5%` |
| `ARQ0.9522X0.1541Y0.1537Z0.2145` | `ARQ0.9522X0.1541Y0.1537Z0.2145Cb404%` |

（第 4 行就是你们**当前**正在发的那组四元数 `w=0.9522 x=0.1541 y=0.1537 z=0.2145`，
按新格式应该是上面这行。）

Python 自检（下位机侧也可以直接跑）：

```python
def crc16_mcrf4xx(data: bytes) -> int:
    crc = 0xFFFF
    for b in data:
        crc ^= b
        for _ in range(8):
            crc = (crc >> 1) ^ 0x8408 if crc & 1 else crc >> 1
    return crc

body = "ARQ0.9522X0.1541Y0.1537Z0.2145"
print(f"{body}C{crc16_mcrf4xx(body.encode()):04x}%")   # -> ...Cb404%
```

### 1.6 发送速率

- 建议 **100 Hz**（你们当前就是 100 Hz，保持即可）
- 视觉端不挑剔速率，20–500 Hz 都能用；但低于 50 Hz 会影响云台跟随质量

### 1.7 视觉端的容忍度（实现时不用管，仅供了解）

- 帧尾 `%` 可省；`\n` 和 `\r\n` 都行
- 帧间允许混发**任意其它数据**（二进制、日志、别的协议都行）——视觉端按 `ARQ` 前缀搜索、按 `%`/`\n` 切帧、跨读块自动拼接，会自动丢弃垃圾字节
- CRC **必须正确**，错一帧丢一帧（不会崩，但那一帧的四元数就没了）
- 数字位数不限（`%.4f` 只是建议），但不要出现逗号、空格

## 2. 视觉 → 下位机：控制帧 `AAP`（下位机需要解析的部分）

视觉端现在就在发这个格式，下位机按下面解析即可。

### 2.1 格式

```
A  A  P  <pitch>  Y  <yaw>  F  <fire>  N  <frame>  C  <4位hex CRC>  %  \n
```

```
AAP1.23Y-4.56F0N120Cc328%\n
```

- `P` 后是 **pitch 增量**，`Y` 后是 **yaw 增量**，单位都是**度**
- `F` 后是 **fire**：`0` = 不开火，`1` = 开火（**只有 0 和 1 两个值**）
- `N` 后是帧号（递增，用于丢帧统计）
- CRC 同 1.3，覆盖 `C` 之前的全部字符

### 2.2 语义（重要）

`pitch` / `yaw` 是**相对于当前云台角度的增量**，不是绝对角度：

```
目标云台角 = 当前云台角 + (pitch, yaw)
            yaw 增量已归一化到 ±180° 以内
```

视觉端算的是 `send_pitch = cmd.pitch - 当前pitch`、`send_yaw = wrap180(cmd.yaw - 当前yaw)`。

- **没有目标时**：增量为 `0.00` 且 `F0`，云台应保持不动
- `F1` 出现的条件：有目标 + 有开火建议 + 增量总误差 `hypot(pitch, yaw) < 1.0°`

### 2.3 测试向量

| `C` 之前的部分 | 完整帧 |
|---|---|
| `AAP0.00Y0.00F0N1` | `AAP0.00Y0.00F0N1C3db9%` |
| `AAP1.23Y-4.56F0N120` | `AAP1.23Y-4.56F0N120Cc328%` |
| `AAP-3.50Y12.30F1N9999` | `AAP-3.50Y12.30F1N9999Cdb00%` |

## 3. 联调验收

视觉端跑起来后，日志里每秒一行统计，重点看两个字段：

```
detect: 124  track: 124  found: 0  solve: 990  serial: 100  bad_frame: 0  camera: 124
                                               ^^^^^^^^^^^   ^^^^^^^^^^^^^^
```

| 字段 | 期望 | 含义 |
|---|---|---|
| `serial` | **≈ 100**（等于下位机发送频率） | 每秒**解析成功**的帧数 |
| `bad_frame` | **0** | CRC / 格式错误数 |

- `serial: 0` → 视觉完全没收到，或格式不对（前缀不是 `ARQ`）
- `serial: 0` 且 `bad_frame` 很大 → 收到 `ARQ` 但 CRC 或数字格式不对
- `serial ≈ 100` 且 `bad_frame: 0` → **通了**
